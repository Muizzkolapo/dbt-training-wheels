📁 File Upload Errors

Invalid file type

What it means: The file you're trying to upload is not a SQL file.

Solutions:

  • Make sure your file has a .sql extension
  • Rename your file to end with .sql if it contains SQL code
  • Don't upload text files, Word documents, or other non-SQL formats

Example:

✅ Good: sales_report.sql
❌ Bad: sales_report.txt
❌ Bad: query.docx

File too large

What it means: Your SQL file exceeds the 2MB size limit.

Solutions:

  • Break your large SQL file into smaller files (one per query or table)
  • Remove commented-out code and unnecessary whitespace
  • Upload files one at a time if you have multiple queries
💡 Tip: dbt_training_wheels works best with individual query files. If you have a large script, consider splitting it by logical sections (e.g., one file per final table).

File already exists

What it means: A file with the same name has already been uploaded.

Solutions:

  • Rename your file before uploading (e.g., add a version number or date)
  • Delete the existing file first if you want to replace it
  • Use a more specific name to avoid conflicts

Example:

Original: customer_analytics.sql
Renamed: customer_analytics_v2.sql
Or: customer_analytics_2025_01_15.sql

🔍 SQL Parsing Errors

SQL syntax error

What it means: There's a problem with your SQL code structure that prevents it from being parsed.

Solutions:

  • Check for unclosed quotes (both single ' and double ")
  • Make sure all parentheses are properly matched
  • Look for missing commas between column names or SELECT statements
  • Verify that table names follow the format: project.dataset.table or dataset.table
  • Test your SQL in BigQuery Console first to verify it runs

Common mistakes:

❌ Missing comma:
SELECT
    id
    name  -- Missing comma here!
FROM table

✅ Correct:
SELECT
    id,
    name
FROM table

❌ Unclosed quote:
WHERE name = 'John  -- Missing closing quote!

✅ Correct:
WHERE name = 'John'

Unsupported SQL syntax

What it means: Your SQL uses features or syntax that dbt_training_wheels doesn't currently support.

Solutions:

  • Simplify complex window functions or subqueries
  • Avoid BigQuery-specific functions that aren't widely supported
  • Use standard SQL syntax when possible
  • Check that your query uses CREATE TABLE or INSERT INTO statements, or is a SELECT query
💡 Tip: dbt_training_wheels works best with standard SQL SELECT, CREATE TABLE, and INSERT INTO statements. If you're using advanced BigQuery features, you may need to simplify them.

File is not readable

What it means: The file might be corrupted or contains non-text data.

Solutions:

  • Make sure the file is a plain text SQL file (not a binary format)
  • Open the file in a text editor to verify it's readable
  • Try saving the file with UTF-8 encoding
  • Re-export your SQL from your source system if the file appears corrupted

✓ Validation Errors

Missing required field

What it means: A required piece of information is missing from your request.

Solutions:

  • Make sure you've uploaded a file before trying to analyze it
  • Check that all required form fields are filled in
  • Verify you selected a query from the sidebar before clicking "Analyze"

Invalid model name

What it means: The model name you entered contains invalid characters.

Solutions:

  • Use only lowercase letters, numbers, and underscores
  • Don't start with a number
  • Avoid spaces, hyphens, or special characters
  • Keep names descriptive but concise

Example:

✅ Good names:
  - customer_orders
  - daily_sales_summary
  - dim_products

❌ Bad names:
  - Customer Orders (spaces)
  - daily-sales (hyphens)
  - 2024_sales (starts with number)
  - sales@summary (special characters)

Invalid materialization type

What it means: The materialization strategy you selected is not valid.

Solutions:

  • Choose from: table, view, incremental, or ephemeral
  • Use table for most cases (good performance, persistent data)
  • Use view for lightweight transformations
  • Use incremental for large datasets that grow over time
  • Use ephemeral for intermediate CTEs (rarely needed)

⚙️ Configuration Errors

Missing dbt project name

What it means: You need to configure your dbt project name before generating files.

Solutions:

  • Go to the configuration page
  • Enter your dbt project name (e.g., "my_analytics_project")
  • Save the configuration
  • Return to your conversion workflow
💡 Tip: Your dbt project name should match what's in your dbt_project.yml file if you already have a dbt project.

Invalid configuration format

What it means: The configuration file has formatting errors.

Solutions:

  • Don't manually edit the configuration file
  • Use the web interface to update settings
  • If you must edit manually, ensure valid YAML syntax
  • Check for proper indentation (use spaces, not tabs)

📊 Analysis Errors

Table extraction failed

What it means: dbt_training_wheels couldn't identify the tables in your SQL query.

Solutions:

  • Make sure your SQL uses clear CREATE TABLE or INSERT INTO statements
  • For SELECT queries, ensure you have a clear target table name
  • Check that table names are in the format project.dataset.table
  • Simplify complex nested queries if possible
  • Ensure FROM and JOIN clauses are properly formatted

Example of clear table references:

✅ Good:
CREATE OR REPLACE TABLE `project.dataset.customers` AS
SELECT * FROM source_table;

INSERT INTO `project.dataset.orders`
SELECT * FROM staging;

❌ Unclear:
CREATE TABLE mytable AS  -- Missing project.dataset
SELECT * FROM somewhere;

No tables found

What it means: Your SQL doesn't create or insert into any tables.

Solutions:

  • Add a CREATE TABLE or INSERT INTO statement
  • If it's a SELECT-only query, consider what table it should create
  • Specify the target table name in your SQL
💡 Tip: dbt_training_wheels needs to know what tables you're creating. Even if your original query is just a SELECT, think about what table this data should populate in your dbt project.

Analysis timeout

What it means: Your SQL file is too complex and took too long to analyze.

Solutions:

  • Break your SQL into smaller, simpler files
  • Remove unnecessary nested subqueries
  • Simplify complex CASE statements or window functions
  • Try analyzing one query at a time

💾 File System Errors

File not found

What it means: The file you're trying to access has been deleted or moved.

Solutions:

  • Refresh the page to see the current list of files
  • Upload the file again if it was deleted
  • Make sure you're clicking on a valid query from the sidebar

Permission denied

What it means: The application doesn't have permission to read or write files.

Solutions:

  • Check the folder permissions where dbt_training_wheels is installed
  • Make sure the source_sql_files directory is writable
  • Run dbt_training_wheels with appropriate user permissions
  • Contact your system administrator if this persists

❗ General Errors

No query selected

What it means: You tried to perform an action without selecting a query first.

Solutions:

  • Click on a query in the "Scheduled Queries" section on the left sidebar
  • Upload a SQL file if you don't have any queries yet
  • Refresh the page if the query list appears empty

Network error

What it means: The browser couldn't connect to the server.

Solutions:

  • Check your internet connection
  • Make sure the dbt_training_wheels server is running
  • Refresh the page and try again
  • Check if your firewall is blocking the connection

Internal server error

What it means: Something unexpected went wrong on the server.

Solutions:

  • Try refreshing the page
  • Check the server console logs for details
  • Report the issue on GitHub if it persists
  • Include the error trace ID from the error message when reporting
💡 Tip: When reporting errors, always include the trace ID (shown in the technical details section of the error). This helps developers diagnose the issue quickly.

🤝 Need More Help?

If you're still experiencing issues after trying these solutions:

  • Check the project repository for known issues
  • Open a new issue on GitHub with:
    • The error message you received
    • The trace ID from the technical details (if available)
    • Steps to reproduce the problem
    • Your SQL file (if you can share it)
  • Join the community discussions for help from other users
