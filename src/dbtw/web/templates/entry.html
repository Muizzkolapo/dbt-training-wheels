{# Where a reader brings their SQL in, in the shape the design opens with: the promise, the box, and the four things this tool does with what goes in it. (new_design/dbt Training Wheels.dc.html) The one screen in this directory with no conversion behind it. Every other screen explains a conversion's Decisions, and rule 1 in base.html exists so those explanations cannot drift from the report beside them. There are no Decisions here to explain -- and this screen still says something, because a reader who has not yet pasted anything is exactly the reader who needs to know what will happen to it. So the four lines come from `dbtw.core.intro`, not from here. That is the same rule as everywhere else rather than an exception to it: a sentence written in this file would either be unmarked, and fail the prose threshold, or marked, and fail the exact-match check against what `dbtw.core` produced. Owning them in the engine is what makes the screen able to speak at all, and it puts the claim the tool makes about itself where every other claim it makes lives. The project is asked for first and is required, and the `required` on it is not the gate three of three personas called theatre. That gate asked a reader to certify they had read something; this asks for the one input without which there is nothing to convert *against*. Every proposal this walk makes -- which layer, what prefix, which materialization -- is read out of the `dbt_project.yml` there, and a conversion without one would be this tool inventing conventions and presenting them as findings. `test_no_screen_gates_the_write_action` holds the walk to the difference: the thing that must not be gated is the write, and it is not. What the design shows here that this does not: tabs for "From warehouse" and "From git", both marked SOON. They are a roadmap, and a roadmap rendered as a disabled control is this screen promising something no code here does. The two sources that exist are the two that are offered. The project path is an identifier this screen displays rather than prose it speaks -- `data-identifier`, for the reason the note on `Run` in tests/unit/web/page.py gives: a reader whose project lives in a directory called `warehouse` must not meet that word's definition here for a reason that has nothing to do with their SQL. #} {% extends "base.html" %} {% block main %}
